# 判断：UserBench 可以作为任务来源，原生环境须 REVISE

**建议将 UserBench 列为可适配的数据源，但目前不把它定为验证 Hidden Query Reliability 的最终主实验。** 它提供现成旅行偏好、隐含表达、候选选项、划分及交互代码；没有提供“同一二元偏好在两个等价问法下具有未知、可共享可靠性”的已验证现象。数据源适用不等于理论的关键经验前提已成立。

## 2. 原生任务与我们的理论差在哪里

根据 [路由与回复代码](https://github.com/SalesforceAIResearch/UserBench/blob/80506d2ab484cab843e60a2401ff3e0290d05b87/travelgym/env/prompt_async.py) 和 [模拟器提示](https://github.com/SalesforceAIResearch/UserBench/blob/80506d2ab484cab843e60a2401ff3e0290d05b87/travelgym/env/utils.py)：

1. 每次问题先由 LLM 判定是否具体触及一个尚未披露的偏好；触及时再调用 LLM，要求依据给定偏好及隐含表达忠实回复。
2. 披露后该偏好从剩余集合移除。同一句问题重问可能得到“没有该偏好，或已经告诉过你”，而非新的同分布回答。
3. 连续偏离话题会触发被动披露，默认间隔为 3；搜索另有每 5 次一次的预设故障。这些机制不是自然的 A/B 回答准确率。
4. 原生关键指标包含偏好披露、选择正确选项和费用奖励。若不披露得到可识别的空答/拒答，这更像缺失或擦除通道，不是理论的二元翻转噪声。

因此，不能把“一个问题被路由器判为具体，另一个被判为泛泛”当作等语义、等证据形式的可靠性发现；也不能简单把披露率代入 p、q。原生自由文本回答亦没有现成的、覆盖全部回复的确定性二元正确性解析器。

| 理论对象 | UserBench 原生内容 | 适配要求 |
|---|---|---|
| 固定二元 θ_j | 选中的自然语言偏好、正确选项 ID | 明确二元决策语义，不能把缺省当作相反偏好 |
| 已知组 S | 领域和细分类别 | 可预先分组，但不能据格式效果重新分组 |
| 未知共享 z_g | 无现成标签 | 必须在独立偏好/措辞上测量迁移 |
| 公共未知 p,q、fresh 回答 | 有状态披露路由＋回复生成 | 固定私有画像与历史、每次独立复位；检验异质性和无效输出 |
| 有标签高/低可靠性校准流 | 不存在对应原生资源 | 不把普通训练对话默认视作这些校准流 |
| 只知道 z 的 Oracle | 原生 human oracle / best_id 是另一种参照 | 必须重建 format-only 参照，不能把知道答案的 oracle 当作 Theorem 2 的 oracle |

Theorem 1 的信息规划和 Theorem 2 的最优分配都依赖上述模型条件；Theorem 3 的最小组结论只能在这个模型内解释。不能由某个有限预算准确率排名宣称其渐近结论获得验证。特别是无外部校准且 p,q 全局未知时，笔记的零 leading premium 条件是完整共享 G=1，不能只说“分组了就有零开销”。

## 3. 二元真值提取：为什么暂不直接跑大 Pilot

为避免“未提到带儿童座椅”被误记成“反对儿童座椅”，实现了一个严格而有限的提取白名单：只有同一场景明确选中下列两个互斥取值之一、且未同时选中另一个，才生成 θ。双方都未出现时保留 unknown，不生成负标签。

- 航班：直飞 / 一次中转。
- 航班：各航段同一品牌 / 不同品牌。
- 酒店：King / Double。
- 租车：电动 / 汽油。
- 餐厅：便宜 / 昂贵。
- 公寓：仅一间卧室 / 至少三间卧室。

**这是六类可审阅映射的覆盖率，不是所有可能适配方案的上界。** 部分航班条件之间还可能存在逻辑依赖，不能把每个提取位都当作独立偏好。

| 每场景提取的二元项数 | 场景数 |
|---|---:|
| 0 | 759 |
| 1 | 1,262 |
| 2 | 828 |
| 3 | 246 |
| 4 | 27 |
| 合计 | 3,122 |

共得到 3,764 项；2,363/3,122 场景至少有一项，1,101/3,122 至少有两项。按原生领域保持分组后，3,352 个非空组只有一项、206 个组有两项，未出现三项或四项的组。因此，本映射没有给出足够大的、跨领域的组内迁移实验结构。不能为了凑足 k=4，把同一类别的冗余比较重复计为独立偏好，也不能临时合并不具共享依据的领域。

另有两种可研究但必须显式承认的新任务：

- **要求存在性**：θ 表示“完整私有画像是否明确要求某项特征”，0 表示没有这项要求，**不是反对该特征**。这需要明确封闭画像假设，并保留 neutral 的语义。它可以增加二元坐标，但属于 UserBench-derived 子任务。
- **候选可接受性**：θ 表示一个候选是否满足整组偏好，可依据 correct/wrong 标注或重新实现的谓词计算。多项判断共享同一组约束，相关性很强；不能直接把它们包装成任意独立二元偏好。

不建议在未明确 θ 的含义前再次调用数千次模型。

## 4. 泄漏和划分检查

### 4.1 观测字段

对上游 reset 的五个实际方法做了 AST 提取执行：只运行复位与偏好初始化方法，没有导入 SDK、调用 step 或请求模型。验证：

- `observation.task_description` 等于包含全部偏好的完整 scenario。
- `info.preferences_summary` 直接列出隐藏偏好摘要。
- `last_reward`、elicitation_ratio、remaining_preferences、elicited_preferences 等也不应作为本研究在线学习器的免费正确性/进度反馈。
- 原始记录的 type、reason、correct_ids、best_id、best_id_thought 及场景 ID 留在评估侧。场景 ID 本身编码领域组合，适配时换成不透明 ID。

**没有据此认定 UserBench 官方评测泄漏。** [官方 eval.py](https://github.com/SalesforceAIResearch/UserBench/blob/80506d2ab484cab843e60a2401ff3e0290d05b87/eval.py) 将 feedback 加入模型对话，没有把完整 observation 或 info 传给模型；[原生任务加载器](https://github.com/SalesforceAIResearch/UserBench/blob/80506d2ab484cab843e60a2401ff3e0290d05b87/travelgym/env/task_data.py) 也会从公开候选中移除 type/reason。风险在于新适配器错误地透传全部对象。本次已提供仅允许 feedback、step_count 的白名单投影及测试。

### 4.2 官方分割检验的边界

| 内容 | 测试集不同项数 | 已在 train 出现 |
|---|---:|---:|
| 场景 ID | 471 | 0 |
| 偏好定义 | 82 | 82 |
| 偏好＋原始隐含表达 | 846 | 846 |
| 完整领域偏好包（含表达） | 1,171 | 113 |

87/471 个测试场景至少复用了一个完整领域偏好包。原生 one-choice 和 multi-choice Parquet 使用相同场景集合，不能把它们当成独立确认数据。

这些复用符合对新组合进行测试的设计，并不自动构成错误。**但它不能支持“未见偏好/未见原始措辞泛化”的声明。** 需要区分“固定偏好词典下的新组合”和“新表述/新任务来源”。本研究应在调用前明确目标：若保留官方 test，就按组合泛化解释；若声称新措辞迁移，需要另行冻结新的改写或合理的成分隔离方案。单纯换 seed 或随机抽不同场景不能自动保证新的语义来源。

初始说明中未发现完整偏好/表达的精确字串直接包含（0/3,122），但这里只是字串检查，不能作为语义无泄漏证明。

## 5. 调用成本和基线公平性

默认模拟器模型名为 gpt-4o。`eval.py --model_name Qwen... --port ...` 配置的是被测 Agent 客户端；模拟器的 OpenAI/AsyncOpenAI 客户端由环境另行构建，**不会自动跟随这个端口**。若未显式设置其本地客户端和模型，可能仍使用默认外部 API。一次有效澄清通常需要路由和回复两次模型请求，外加 Agent 请求；原生内部最多三次尝试。不能按“一轮等于一次 4B 调用”估算成本。

本次没有运行 eval.py，也没有运行任何原生交互或实验模型。Parquet 读取使用审计目录内隔离安装的 pyarrow 21.0.0，没有修改其他人的环境。

后续比较应分别记录：路由成功、偏好是否披露、回复是否正确、解析是否有效，以及端到端恢复准确率。若保留原生路由，同时做固定路由对照，防止把问题触发差异当成回答准确性差异。任何覆盖路由/移除被动披露的实验都要标明是适配子任务，而非原生 UserBench 成绩。

直接询问最佳格式是元问题，可能被原生路由归为非偏好/泛泛问题。**不能因为环境不允许它正常回答，就宣称现实中的直接询问基线无效。** 直接自报和公开信息预测应有独立、同信息边界的测试接口；自报的正确性用独立观察衡量，不能预设已知 s_g。原生单一旅行领域对应的稳定最佳形式若能由公开描述猜出，也不支持复杂在线学习的必要性。

## 6. 建议的下一步：小型可回答性诊断，不进入 Phase 2

已从官方 TRAIN 按固定哈希选择八个保守二元样例，生成 `preview_public.jsonl`、`preview_private.jsonl`。两种问法共用完全相同的替代项及“其他条件相同”的证据。真值来自所选原始偏好，不调用 LLM 生成或评分。公开部分没有真值或私有画像。**这些仅供审阅，不是已经执行的 Pilot，也未冻结成新的效果实验。**

若继续，建议先执行一个新冻结的诊断包，而不是完整旅行 Agent：

1. 八个 TRAIN 样例 × 两种形式 × 两种选项次序 × 两次独立回答 = 每个解码配置 64 次。
2. 可预先固定两个 4B 配置比较严格短答和允许简短推理，各 64 次；直接自报、公开信息各 8 次，总上限 144 次。所有设置与解析规则先冻结，两个配置都报告，不选优后把同批结果称为确认实验。
3. 只判断基本理解、解析和选项偏置；这八例不足以证明组共享或效果优越。若准确率近随机或两格式均达到天花板，都停止扩量。
4. 在独立语义定义下解决组大小不足后，另行冻结不同偏好及不同措辞的共享性检查；再讨论是否值得发展信息分配方法。
5. 35B 复核、训练、Phase 2 和大批量调用均不包含在本次审计中。

**研究建议：接受“UserBench 为现成任务来源”，暂缓“UserBench 已是适合核心理论的主实验”。** 若坚持每用户八项真实互斥二元偏好和多个 k>=4 的自然共享组，本次保守适配不满足，应考虑更合适的结构化约束数据，而非反复调整提示制造优势。
