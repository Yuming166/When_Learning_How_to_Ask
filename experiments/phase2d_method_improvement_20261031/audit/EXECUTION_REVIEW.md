## Core protocol findings

| Item | Finding |
|---|---|
| Four arms | Exact historical classes for Aligned-Full and D-RRC-NoType; Aligned-NoType removes type availability in the optimization input; D-RRC-Type overrides the target update only |
| Common estimator | Forced-task-only theta/z/p/q estimator, grid, ties, forced exploration, tracker and update cadence are shared; paid reports do not change the task format estimate |
| Type baseline | D-RRC-Type uses observable allocation proxies and the public known accuracy, with no joint information optimization; its R-scale thresholds are scheduling heuristics, not error certificates |
| Common acquisition stopping | All main arms use the same Phase2c legacy float GLR, check cadence and numerical margin; the main batch is not a certified stopping experiment |
| Strict replay mode | Float crossing is only a prefilter; `complete` comes from `certified`; rejected/undetermined gates continue; cap scoring guesses remain distinct from certified output |
| Nuisance types | The main decoder retains every unknown type vector in all arms, including NoType |
| NoType permissions | Evaluator rejects `ask_type` before charging/dispatch, in addition to the worker guard |
| Feedback boundary | Snapshot RPC returns only `{recorded: true}`; submission returns only acknowledgement; labels, type errors and scores remain evaluator-side |
| Independent unit | Globally distinct world indices across cells/replicates; common world and action-stream draws only within the four-arm comparison |
| Frozen historical behavior | Imports are read-only; no historical source edit is required by the new strategy definitions |

Different actions consume different stream prefixes, so the shared estimator
does not imply pathwise equal estimates or identical forced observations.
The protocol and baseline specification state this correctly. The 2×2
interaction describes the four specified policies, whose type schedules
differ by family; it does not identify an additive or universal causal share
of task/type information.

## Analysis, replay and issue dispositions

1. **Analysis reviewed:** reviewed the complete cell summaries, full denominators,
   paired contrasts/interaction, 4,000-resample world bootstrap with fixed
   analysis seed 763401, post-data coefficient references, failure accounting,
   and claim labels. Four worlds per cell support exploratory, low-resolution
   intervals only; bootstrap resamples do not add independent observations.
   `analyze.py` requires exact coverage of all 256 planned identities and
   matching metadata, validates cap censoring and acquisition costs, and
   refuses any completed-only analysis. The same per-cell sampled world
   indices are applied to every arm and all five contrast vectors. The
   interaction signs agree with both equivalent difference-in-differences
   formulas. Coefficients are computed only in the post-run analysis path.
   `report.py` labels all main costs and wrong outputs as legacy floating
   results, reports all cells and denominators, and separates CPU from queries.
2. **Partial trajectory preservation — source concern resolved:** the initially inspected evaluator
   loses its current counts/reports and trace when `evaluate_job` raises. Global
   charged counters, the current job and earlier snapshots survive, but a
   failure before a snapshot has no complete partial state receipt. Preserve
   exact partial state/cost and failed status, and enumerate never-run planned
   trajectories in the analysis. The revised evaluator now accepts an
   `on_failure` callback and preserves counts, reports, acquired calibration,
   observed costs, submitted status and partial trace digest before re-raising.
   The main runner writes both public failure and private reproduction rows.
   Source-level gap resolved. The added failure fixture demonstrates one
   acquired task answer and six reference observations survive a failure
   before any snapshot, without labeling that path cap-censored.
3. **Failure versus censoring reviewed:** ordinary cap censoring contributes B to the
   observed restricted cost. A computation failure or unstarted trajectory
   has an unobserved terminal cost and must remain explicitly failed/missing,
   rather than being silently presented as observed cap censoring. Preserve
   the planned denominator. The implemented incomplete path emits the full
   missing/duplicate/unexpected identity report and stops the comparative
   analysis; it does not substitute a smaller paired sample.
4. **Post-data audit and replay reviewed:** independently recompute every new
   floating terminal GLR; enclose every declared completed old non-Oracle and
   new terminal state; replay the prespecified existing R64/R1024 paths under
   the correct modes and separate cap/deadline, preserving rejects/overlaps
   and any extra calls. Endpoint certification is not a retroactive claim that
   the acquired trajectories executed strict certified stopping. The replay
   selection is the first stored R64 and R1024 path per arm, with no outcome
   selection. R64 replay compares all non-timing outputs and snapshots;
   R1024 replay tests strict crossing/abstention and logs extra calls. Its
   worst-case eight-path budget is 106,496 online calls, below the separate
   200,000 allowance. A revised failure handler preserves aggregate replay
   costs/time, current selection, error and earlier completed replays; partial
   observations survive in a failure log. Successful rows now retain the full
   replay record, including counts, reports, reference data and action costs.
5. **Integrity source and receipts reviewed:** before drawing the fresh development seed,
   verify all 353 historical receipt-bound files and original theory, review
   deterministic/confined-worker test results, and persist hashes of all
   implementation, protocol, config, audit and analysis sources. The runner
   checks its freeze manifest. `HISTORY_PRESERVATION_BEFORE.json` reports
   353 verified historical files, the original theory hash matched against
   Phase2c's frozen expected hash, and no fresh seed file. The freeze function

   The main runner now checks the theory hash before acquisition as well.
   `RUNTIME.json` records all three backend thread variables as 1. Neither
   seed content nor private label files were read by this reviewer.

## Public-structure baseline guard

The late pre-seed guard is acceptable: D-RRC-Type calls the literal frozen
D-RRC target update when and only when `G==1 && reference_count==0`. Both
conditions are public. The raw Theory_Note Section 6, Corollary 3.1 gives
the zero leading premium for a single group at alpha=0; Theorems 2–3 give
the uniform-good allocation and zero first-order paid-type count. This is
a model-specific leading-coefficient motivation. It does not show that a
finite-R paid query is useless or that the frozen floating Aligned solver
has identical numerical behavior.

Within the guarded cells, D-RRC-Type and D-RRC-NoType share the same action
rule and paired stream draws. Their type-benefit contrast is structurally
zero by design, not a conclusion learned from four sampled worlds. The
general full-R-scale type workload rule remains active outside this guard,
including a single group with positive reference data and multiple groups
without references. Its scheduling quantities remain heuristics, never
stopping certificates. The final protocol, baseline specification and report
template explicitly preserve these boundaries.

The final guarded suite has **39/39 passing tests in 9.761 seconds**:
15 strategy, 5 analysis, 13 numerical-certificate, 5 integration and 1
failure-receipt test. The final suite's confined integration fixtures account
for 512 technical online actions and 24 reference observations; its failure
fixture adds 1 action and 6 references. The earlier 36-test suite passed in
9.481 seconds and is a separate technical execution. These are technical
validation counts, not main development or confirmation worlds. The
independent numerical gate regression also passed, as recorded separately.

At this final review, the main seed file, `freeze.json` and `artifacts/run`
were all absent. The reviewed 353-file historical receipt and original-theory
comparison were already recorded. The freeze procedure must now bind this
review and the exact reviewed sources before its single fresh development
seed draw. The existing Phase2c confirmation protocol remains untouched.
