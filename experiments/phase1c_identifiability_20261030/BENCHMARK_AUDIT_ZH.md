# Phase 1c：多目标 benchmark 适配审计

判断：ProofWriter **原生问答列表在本次 OWA depth-3 切片中不足以直接支撑设计**；其完整证明结论可作为受限机制实验的目标来源。ContractNLI **数量可行，保留应用候选**，尚未建立共同可靠率或共享最佳形式。UserBench 保留辅助地位，原有负结果全部保留。

## 数据来源与范围

- [ProofWriter 原论文](https://aclanthology.org/2021.findings-acl.317/)；[官方数据入口](https://allenai.org/data/proofwriter)。取官方 `proofwriter-dataset-V2020.12.3.zip` 的 OWA depth-3 TRAIN/DEV，不取 TEST。源 ZIP 成员通过 HTTP range 获取并校验未压缩长度、CRC32、SHA256。不是二次加工的 Hugging Face 镜像。
- [ContractNLI 官方站点](https://stanfordnlp.github.io/contract-nli/)；[原论文](https://aclanthology.org/2021.findings-emnlp.164/)。官方 ZIP 中 train/dev/test JSON、README、CC BY 4.0 LICENSE 已取得并校验。TEST 只统计结构、类别和长度，未运行模型或挑选案例；这一结构访问也明确记录，不称为完全未接触的保留集。将来确认仍需锁定协议与独立采样方案。

所有来源、成员路径、版本、大小、校验和见 `sources/*fetch_receipt.json`。目录中没有模型调用凭证。

## ProofWriter 的原生目标为什么不够

|审计项|TRAIN|DEV|
|---|---:|---:|
|规则世界|4,816|719|
|原生问题（含互否命题与 Unknown）|69,388|10,302|
|True / False|19,264 / 19,264|2,876 / 2,876|
|Unknown，单独保留|30,860|4,550|
|至少 6 个去互否重复的确定原子目标|12|1|
|至少 8 个这样的目标|0|0|
|原题与独立求解器标签不一致|0|0|

TRAIN 中 4,133/4,816 个世界只有 4 个确定的正极性原子目标。把“某命题”和“该命题的否定”当作两个独立目标，会夸大组大小。Unknown 没有被当成 False。

独立求解器对正/显式负文字分别做有限签名 Horn 前向闭包。规则前件 `~` 在本 OWA 数据中按 hard negation 处理，符合官方 README；没有套用 CWA 的 negation-as-failure，也没有逆否推理。全部原题匹配只是交叉核验，标签由求解器实际计算。

## 明确适配：使用官方完整证明结论

原记录另附 `proofDetails`，包含所有可证明结论及证明信息。独立闭包与这些结论集合完全匹配：TRAIN 58,929，DEV 8,832，世界级差异均为 0。

把其中已证明的正文字、负文字规范为同一正原子命题的 True/False 目标，可得到：

|适配后的结构|TRAIN|DEV|
|---|---:|---:|
|至少 6 个确定原子目标|4,358|663|
|至少 8 个确定原子目标|3,411|522|
|最终六目标结构筛选通过|335|51|

最终筛选：3 True、3 False，至少 2 个非直接事实目标，各目标在所有已支持规则路径中的事实祖先集合互不相交。每个目标还保存一个可重放证明证书。TRAIN 有效世界覆盖率只有 335/4,816（6.96%），不能将这个受限子集称为完整 ProofWriter 基准。

仅依赖标签/证明结构筛选，不访问 Qwen 回答。以预定 hash 排序选前 8 个 TRAIN 世界；目标排序不编码 True/False 交替。规则可共享；8 世界的所有目标对均没有已支持规则图上的有向可达关系或共享事实祖先，具体见 `selected_dependencies.json`。这排除了本次检查可见的推理连接，**不证明统计独立、共同 p/q 或共享 z**；语言、同一世界语境及模型错误仍可能相关。

两个提问形式对同一 claim 的可证明状态提问，使用逐字相同的完整事实、规则、claim、选项和答题说明，只改问题 header。两次重复保留选项顺序与 prompt，以区分独立采样和换问题。结构检查可核对逻辑映射；它不能代替人的语义等价性评审。所选形式较接近，可能根本不存在有用可靠性差异，这也是可接受的负结果。

这是 **adapted ProofWriter mechanism task**。信息源持有世界事实，选择器只看 ID 和历史无标签答案；如果选择器也得到完整可执行规则，则可直接求解而不需要询问。此接口假设必须写入论文。它不表示模型在模拟真实人类的偏好。

## ContractNLI：有多目标，尚无可靠性共享证据

|项目|TRAIN|DEV|TEST（仅结构审计）|
|---|---:|---:|---:|
|合同数|423|61|123|
|至少 6 个 E/C 标签的合同|384|56|101|
|至少 8 个 E/C 标签的合同|348|47|94|
|Entailment|3,530|519|968|
|Contradiction|841|95|220|
|NotMentioned，排除二元构造并保留计数|2,820|423|903|
|文档词数 min / median / max|211 / 1,504 / 8,428|342 / 1,727 / 4,796|205 / 1,417 / 6,267|
|共享标注证据的确定目标对 / 总对数|2,030 / 22,521|334 / 3,048|628 / 5,863|

原生 17 个固定假设不是 17 个独立二元偏好。TRAIN 的 E/C 子集共 4,371 项，仅恒猜 Entailment 就达 80.76%；高准确率本身不能说明提问方法有效。NotMentioned 共 2,820/7,191，不能压成 False。排除它后需要公开选择规则、覆盖率和任务分布变化。

人类金标可用于确定计分，但不是可执行形式逻辑的真值证明。证据重叠至少说明部分目标不能视为无关题目；不重叠也不保证不存在语义依赖。假设涉及同一 NDA 的使用、保密、披露、销毁等条款；固定假设 ID 和措辞可以成为很强的公开元数据线索。未来必须保留逐假设、跨文档的 metadata 基线，而不能只和 RR 比较。

可行的二元适配仅限 E/C 确定项：A 询问合同是否支持原假设，B 从“支持 / 反驳”两个状态中选择；两形式都给相同完整文档。不得在某形式中额外展示 gold 证据，也不应将 gold 证据截取伪装成一般文档理解。本文未进行 ContractNLI 模型调用，也未先行确定其共享组通过经验验证。

## 边界与下一步判据

精确 Bernoulli 的无标签可辨识性见 `IDENTIFIABILITY_NOTE_ZH.md`；自然语言的 192 次开发测试另见 `run/REPORT_ZH.md`。用户示例的乘法 8×6×2×2 实际为 192；本轮保留四个维度，不加倍重复数以凑 384。

结构通过只允许开展有界发现测试。进入 Phase 2 还需要基本正确率、稳定形式差异、无标签跨目标迁移及简单类型基线的排除；这些不是由数据集规模或标准答案存在性自动保证。无论测试结果如何，本轮不继续调 prompt、不换模型追正结果，也不启动复杂自适应 Agent。
