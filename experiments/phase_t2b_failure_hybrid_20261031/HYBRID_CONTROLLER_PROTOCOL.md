## Risk rule: fixed, cheap, untrained

At each scheduled update, first compute frozen DeepSets-KL weights w. Let u_j=4 theta_prob_j(1-theta_prob_j), v_g=4 z_prob_g(1-z_prob_g). Request fallback when ANY condition holds:

1. Some u_j>0.5, or some v_g>0.5.
2. Some u_j>0.05 with total two-format fact weight <0.25/d.
3. All v_g<0.05 and total paid-type weight >G/(2d+G)+1e-12.
4. max action weight >0.8.

Thresholds are literal algebraic conventions, not fitted success probabilities. They were chosen after the declared posthoc old-trajectory audit, with zero sweep and before all new outcomes. The type threshold is the uniform legal-action mass; the tolerance only separates floating equality. This rule may miss late certification bottlenecks and may over-trigger on harmless early uncertainty. No query noninferiority or stop-time guarantee follows.

Hybrid-Risk-Info uses greedy Fused-Info only on flagged updates; Hybrid-Risk-Reuse uses AnalyticReuse on exactly the same flag definition. Neither runs a reference optimizer in order to decide whether to call it. Periodic-Info ignores risk and uses Fused-Info on update indices0,4,8,...; otherwise it uses frozen KL. Always-use controls are the two pure reference methods. Every fallback, neural forward before fallback, risk computation, normalization and wrapper overhead is charged. Fallback frequency is an outcome, not tuned to match favorable results. No posthoc best-hybrid winner is promoted without multiplicity/selection qualification.
