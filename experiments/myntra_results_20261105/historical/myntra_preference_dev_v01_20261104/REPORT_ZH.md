## 2. 解决“能接受但不想买”的定义问题

一件商品首先要满足hard：商家建议的洗护标签在用户接受集合内，且面料标签
不在排除集合。此时仅表示可考虑。用户可同时接受手洗、干洗等多个建议类别，
不假设偏好只能是单一标签。

对可考虑商品，画像对五项类别标签给出固定加分/减分，求和得偏好分数。只有
最高分严格高于购买门槛才购买；等于门槛也不买。若有并列最高分，任何一个
并列商品都是有效选择。没有合格商品和有合格但不值得买是两种不同原因。

这些整数分数是**受控一致性协议**，不是从真人行为拟合出的效用。数据没有
领口高度、触感或视觉吸引力，程序和模型均不能编造这些信息。当前模拟的是
“这些明确标签是否足以满足固定要求”，不能替代视觉服饰审美实验。

原目录的Wash Care只表示商家建议，不表示其他洗护方式一定不允许。画像约束
明确作用于“用户愿意遵循哪些商家建议”，而非根据缺失资料推断物理禁忌。
面料约束同样是标签偏好，不是成分百分比或过敏安全判断。

## 4. 16次真实Qwen回答

采样前固定P00和P08，各8次请求：四种菜单呈现、A/B洗护披露、一次完整画像
披露，以及使用实际披露生成推荐后的最终顾客决定。独立请求重置历史；最后
一项使用该画像实际上一轮回复，未伪造历史。提示词、评分脚本和请求计划先冻结。

| 测量 | 正确／计划 | 说明 |
|---|---:|---|
| 输出可解析 | 16/16 | 无围栏、无截断、无重试 |
| 独立商品选择 | 7/8 | 包含重复、反序和代号置换 |
| 洗护集合披露 | 3/4 | 一次额外声明接受干洗 |
| 完整画像披露 | 2/2 | hard、全部标签分数、购买门槛一致 |
| 披露后程序推荐 | 2/2 | 仅由实际披露计算，两次均建议不买 |
| 推荐后顾客最终决定 | 2/2 | 两次均不买 |
| 全部商品选择合计 | 9/10 | 8次独立＋2次实际对话末轮 |

**覆盖限制：这两位预定画像在各自第一菜单上都应该不买。** 10次商品选择
都是同两个“有合格商品但吸引力不足”场景的不同呈现/历史，不是10个独立用户。
本轮没有应购买的Qwen正例，也没有对完整12画像运行模型。没有追加调用改变
这一分母或补齐有利结果。
作为覆盖诊断，恒定回答“不买”在这10次也会全部正确；因此9/10不能解释成
模拟器具备完整推荐判断能力。后续必须补上预先固定的应购买场景。

实际模型响应ID为16个不同ID，服务标识均为Qwen3.6-35B-A3B。输入16420 tokens，
输出1104 tokens，总计17524 tokens。服务标识核验不等同于独立权重审计。

## 5. 两个需要保留的失败

**反序呈现下出现购买错误。** P00原顺序、重复、代号置换都不买，反序呈现时选择购买。
所选商品确实满足硬要求，也是可接受商品中的最高分；但最高分只有4，画像
购买门槛是6。这正是“相对最喜欢，但仍不值得买”的错误混淆，不能因为选到
最高分商品就判正确。该商品的相对效用regret为0，购买决策仍然错误。

**问法B的回答偏离画像。** P00只接受hand wash；问法A答对，问法B却多报了
dry clean。完整画像披露又答对。因此，能复述全画像不保证所有局部问法一致。
两画像四次披露不足以支持共享可靠性、稳定A/B差距或可迁移的p/q估计。

没有为修正这些答案而修改提示词、重问或替换画像。所有请求和原响应均保留。
各独立请求的采样seed不同；本轮不能分离呈现变化、问法和采样随机性各自的
因果影响。“反序时错误”不等于已经证明“反序导致错误”。

## 6. 与理论和后续方法的关系

目前开发的是应用接口：未知顾客偏好通过问答披露，公开推荐器根据观察更新，
再给出推荐或不购买。这个受控画像包含多值偏好和未知购买门槛；披露回答也
可能一次传递整个分数表。它不自动等同于原理论的二元原子查询和共享iid可靠性。

一次完整披露已在这两例成功，应保留为强基线。后续不得仅为使自适应策略
胜出而禁用或任意加价；若比较交互轮次、回答长度或用户负担，成本定义需要
事先固定，并说明它与原理论查询成本的对应关系。

下一步优先是一个新的、预先规定覆盖范围的模拟器诊断：同时含应买、合格但
不想买、无合格项和并列选择；继续检查呈现变化。需要明确这是机制覆盖抽样，
不能冒充用户行为总体分布。确认模拟器足够一致后，再考虑接入现有方法、IG、
Round-Robin和完整披露，按同一观察和成本协议比较。

本轮到16次开发诊断停止，没有启动更多画像、训练或方法优化。
