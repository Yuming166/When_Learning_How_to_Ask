# Myntra 受控闭环方法开发 v0.1：有限先验下的决策导向提问有早期优势

## Material Passport

- 日期：2026-11-04；分支：`myntra_coverage_diag_v02_20261104`。
- 状态：开发面板完成；24/24 画像—菜单案例，12个画像，6个菜单。
- 结果性质：确定性 Python 用户模拟器；没有 Qwen/Luna/API/GPU 调用，也没有训练。
- 主结果：在5个字段问题预算下，Decision-Set IG 与 Decision-Value 各答对23/24，
  固定顺序和画像 IG 各答对21/24。两个新增正确案例都来自同一个画像 P10 的两个菜单，
  所以这只是一个开发信号，不能称为稳定或泛化优势。

## 本轮闭环是什么

顾客由 `ReferenceUser` 程序扮演；它按照构造画像对问题作确定、无噪声的精确回答。
推荐方由 Python 查询策略和贝叶斯后验决策规则扮演。策略只拿到公开菜单、独立种子
生成的先验画像样本及用户实际披露的字段。隐藏画像和参考答案只交给评估器。

四种策略使用同一批24个案例、同一套六个问题、每问一个信息单位、每个品类2,048个
先验样本及同一推荐规则：

1. 固定字段顺序；
2. 最大化对完整画像的信息增益；
3. 最大化对最优推荐集合（包括并列商品或 `NO_BUY`）的信息增益；
4. 最大化下一问带来的预期正确推荐概率提升。

“询问全部画像”另作为强快捷基线，记录为1轮、6个信息单位；因此不把一轮长披露和
一个字段问题当作相同的信息成本。

## 完整结果

正确率分母始终是24个案例。原始类别构成为6个应购买、18个应不购买；所以零询问时
一律回答 `NO_BUY` 已有18/24正确。总体正确率必须与购买召回和不购买特异度一起读。
表中的分数遗憾只记“应购买案例中漏掉的正向分数盈余”，应不购买案例定义为零；误报购买
单独由不购买特异度计量。因此不能单独用分数遗憾衡量全部决策错误。

| 5问策略 | 正确率 | 购买召回 | 不购买特异度 | 总分数遗憾（24案） | 硬约束违反 |

两个决策导向策略的5问错误都是 P00 的一个 `NO_BUY` 菜单，被预测成购买；它们相对
固定顺序新增的两个正确案例，则都来自 P10 的两个菜单。换句话说，策略没有在其余11个
画像上取得正确案例增益。整体改善受一个画像簇驱动，且不购买特异度没有提升。

六个字段全部披露后，四种逐字段策略均在24/24案例上恢复参考结果。完整画像一轮披露
同样24/24，但它一次传递了六个信息单位。全部逐案记录、成本和不同预算下的配对结果
见 `results/PAIRED_CASES.jsonl` 与 `results/DEV_METRICS.json`。

## 解释与边界

本实验说明：在这套确定性、多属性、构造偏好分布中，决策相关提问排序可以比固定顺序
更早覆盖购买案例；一般画像信息增益没有带来该收益。结果值得后续用冻结的模拟用户协议
做小规模外部行为检查，但现阶段只能算开发信号。

它没有测试原理论中的共享未知问法可靠性，也没有测试 Decision-KL 对修正版 IG 的优势。
答案是人为构造画像的精确披露；先验也是同一构造分布的单个2,048样本近似。当前只有12个
画像、6个菜单，且5问改善完全由一个画像簇贡献；没有独立确认集、跨商品目录测试或人类
用户证据。不能据此称为 Qwen/Luna 推荐 Agent 结果，不能声称真实购买行为改善，也不能
把它写成方法已稳定胜过强基线。
