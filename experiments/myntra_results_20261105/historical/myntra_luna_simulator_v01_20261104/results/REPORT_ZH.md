# Luna 模拟顾客诊断

本报告是开发阶段的机制诊断，不是推荐方法比较，也不代表真人。
8个画像按四种参考决策机制分层选择；每类2个画像。保留商品没有进入输入。
Luna通过 Codex CLI 的 `gpt-6-luna` 模型名请求。CLI 没有暴露与 Qwen 相同的温度、top-p、seed 或原始 Chat Completions 协议，且没有独立权重/后端身份证明，因此这是调用路径诊断，不是严格控制的模型能力比较。

## 后处理更正

初次汇总脚本误把反序和代号变换两种呈现也计入三次基础重复，导致稳定性数字不正确。此处已按原始顺序的 `base_1/base_2/base_3` 重新汇总；原始分析保存在 `ANALYSIS_PRE_POSTHOC.json`，修正记录见 `POSTHOC_AUDIT.json`。动作评分、预设门槛、模型输出及请求数均未改变。

## 解释边界

该样本刻意覆盖买唯一最优、买并列最优、存在可买但不值得买、没有可买商品四类机制，不能估计真实购物者的购买率。重复调用是同一画像的重复测量，不是新增独立用户。
Luna 的固定画像和任务被序列化为单条用户消息交给 Codex CLI；Qwen 历史实验则通过独立的 system/user 消息发送。这个角色封装差异会影响行为，因此两者分数只作描述性参照。 Qwen与Luna的差异同时混有模型、服务协议、采样控制和Codex代理系统差异，不作因果归因。成功披露画像或接受程序推荐，也不等于验证了真实用户偏好，更不等于方法优势。

完整逐条记录见 `ANALYSIS.json`、`LUNA_ROWS.jsonl`、`QWEN_REFERENCE_ROWS.jsonl`；原始请求/响应与 CLI 事件保存在 `artifacts/luna_run/`。
