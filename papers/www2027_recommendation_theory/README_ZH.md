## 这篇文章讲什么故事

Web 推荐助手面对新用户时，缺的可能不只是偏好数据。它也不知道该怎样问，才能得到可靠的偏好表达。例如，规格问题与使用场景问题可能对同一个人有不同的理解难度。这里的例子解释研究动机，并不意味着两种自然语言问法已经满足论文的等价性与独立性假设。

如果一种提问方式能在多个偏好之间复用，学习它的开销也许能够被分摊。但“可以迁移”并不等于“没有额外成本”。文章把这个直觉变成一个明确问题：在同样的有限校准信息下，不知道可靠问法的系统，何时能够达到知道可靠问法的 oracle 的一阶交互成本？

核心答案有些反直觉：决定额外成本能否消失的是**最小共享组**，而非平均共享规模。缺乏对数置信尺度的校准时，只有全部偏好共用一个可靠问法类型，才能消除一阶额外成本。一般的有限校准情形则由正文的显式标量判据决定。

这个结论的价值是提出一种结构诊断：在研究更复杂的推荐 Agent 之前，先确认任务是否具有足够的可靠性共享，以及基线究竟获得了哪些信息。它不意味着一个现有程序已经在真实用户或推荐准确率上领先。

## 为什么选择这个推荐任务

文章研究固定槽位、每槽两个候选、效用可分且权重为正的推荐列表。该设定让“正确恢复偏好”与“返回整个最优列表”严格等价，避免把一般二元识别的下界直接套到任意 top-1 推荐上。

这是一个范围有限的推荐问题；其结构本身不是 Web 独有。Web 联系来自平台在有限交互预算下获取新用户偏好，以及问题界面的跨需求复用。第一页明确说明了这项科学问题。是否足以满足 WWW 的应用重要性标准，仍需要作者与领域合作者判断，不能用推荐术语替代这个判断。

## 理论与 methodology 如何衔接

正文用联合信息分配与探索跟踪给出达到复杂度系数的理想策略构造。连续未知率进入同一个信息规划；所有回答与离线校准进入同一联合似然；停止比较所有错误偏好向量，而不把某次类型估计永久当成真值。

这是**理想实数运算及实际优化误差趋零条件下的达到性结论**。既有工程实现及强基线比较见[方法导航](../../docs/METHODOLOGY.md)，尤其是 [Phase 2e 开发结论](../../experiments/phase2e_type_evidence_20261031/FINAL_RESEARCH_DECISION.md)。它们有各自的有界开发范围；固定数值容差程序不自动获得本文的渐近认证。初稿没有把这些工程结果改写成真实推荐效果提升，也没有把通用 tracking 方法本身宣称为首次提出。
