# 叙事、贡献与自审

## 文章的推进顺序

第一层是一个读者容易理解的推荐问题：问到了答案，却未必获得可靠偏好。第二层是复用问题：同一种表达方式是否能服务多个需求。第三层才提出理论问题：这种复用是否足以消除学习提问方式的额外成本。

随后用受限推荐列表把“准确恢复偏好”变成一个明确的推荐决策目标。先定义公平的信息预算，再给出联合 KL 系数和达到性策略，最后用 oracle 唯一性把一个大信息规划压缩成最小共享组的标量判据。图示、直接类型询问与负面诊断用于解释定理在哪些情况下有意义。

## 引言的反向提纲

| 段落 | 段落承担的任务 | 后一段为什么必要 |
|---|---|---|
| 1 | Web 推荐中，问题表达影响偏好获取；以已有使用场景问题研究为依据 | 一个好问法为什么值得学习，取决于能否复用 |
| 2 | 复用带来预算问题；同一答案兼有学习偏好和学习可靠性的作用 | 需要区分已有研究与本文要精确回答的问题 |
| 3 | 承认主动偏好获取、质量估计和联合效用学习；收紧到额外成本边界 | 该问题必须落在具体且可证明的推荐目标上 |
| 4 | 定义受限推荐任务，说明通道假设 | 可以陈述结构结论及其学术意义 |
| 5 | 给出最小组结论，并归因通用控制/跟踪框架 | 接入模型与定理，避免读者到第三页才知道贡献 |

## 五个维度的自审

| 维度 | 本稿处理 | 尚需作者判断 |
|---|---|---|
| 贡献 | 聚焦最小共享组与有限校准的精确成本边界 | 最近邻检索未穷尽，不能保证优先权 |
| 清晰度 | 先说推荐决策，再定义信息与公平 oracle，最后推导边界 | 第三节证明密度较高，需合作者逐句审阅 |
| 证据 | 定理、数值图和既有负面诊断分开；没有补造正结果 | 核心理论需要独立数学复核 |
| 评价 | 公式图可以从公开脚本重算；Qwen 只保留开发诊断 | 不具备真实推荐或用户效果证据 |
| 方法正确性 | 显式保留联合未知率、校准随机性、理想精度与停止条件 | 不能把固定容差程序直接当成渐近达到算法 |

这是同一写作会话的自审，不是独立审稿。没有给出伪精确的录用概率或“已达到投稿标准”的认证。

## 为什么目前没有铺开全部 methodology

已有工程线包含强基线、全证据联合估计、严格停止与计算摊销等内容，但自然推荐通道尚未通过稳定共享验证。把它们全部塞入四页，会让读者误以为理论、开发实现和真实用户环境已经闭环。

本稿保留理论中的构造性策略；既有程序作为公开研究材料供后续接入。若作者决定把方法性能作为第二项主贡献，需要另行冻结一个符合界面的推荐环境，并与直接询问、固定形式、轮流形式及强规划基线比较，不能从本文的公式图获得这种结论。

## 本稿可进一步加强的地方

最优先的是检查推荐目标是否具有足够的应用意义，以及最小共享组结论与最接近的结构化纯探索文献之间的差别。其次是独立审阅 oracle 唯一性与 expected-time 证明。现有合成诊断的负面结果适合提醒研究者检查接口，不足以承担实证贡献；是否将它留在最后提交版本，由作者结合篇幅决定。
